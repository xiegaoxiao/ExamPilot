# ExamPilot — 软件需求规格说明书（SRS）v0.1

> 项目阶段：需求分析（尚未进入架构设计或编码）  
> 日期：2026-10-21  
> 目标用户：备考计算机专业课程期末考试的个人学生  
> 文档状态：**候选基线，需需求评审通过后冻结**

## 1. 项目背景与目标

ExamPilot 是一个**本地优先、单用户、面向计算机专业课程**的智能备考系统。用户上传每门课程的章节 PDF，由**外部 Codex Agent** 基于项目根目录 `AGENTS.md` 和项目提供的 CLI/受控业务接口处理知识、生成练习题；用户通过网页进行练习；后端负责可靠存储、自动判题、错题追踪与每日复习调度。

### 1.1 要解决的问题

1. 课程资料分散，逐章手工总结考点和出题效率低。
2. 题库与章节知识点脱节，难以回溯答案出处。
3. 做错题后没有系统的间隔复习，临考前不知道先学什么。
4. 只刷会的题产生虚假掌握感，缺少基于知识点的薄弱项识别。

### 1.2 可验证的产品目标

- O1：单用户在本机创建不同科目和章节，上传 PDF 并可查看其处理状态。
- O2：通过 Codex 的自然语言指令，将指定 PDF 转成**带来源与审核状态**的题库草稿。
- O3：用户在网页完成客观题练习，正确性、错题、答题历史被持久保存。
- O4：用户每天打开系统，不依赖 Codex 在线也能获得当天的待复习任务。
- O5：课程隔离、题目状态、答案版本与历史均可追踪，并可备份恢复。

## 2. 范围

### 2.1 MVP（P0）

- 本机单用户，网页使用；科目、章节管理；考试日期及每日复习时长设置。
- 上传**可提取文本的 PDF**，记录文件哈希、来源、所属科目和章节；扫描型 PDF 给出明确提示（OCR 非 P0）。
- 结构化题目导入、去重与基本验证、审核/发布/归档；**单选题与判断题**作为 P0 题型。
- 每题保存章节、知识点、原 PDF 与页码、证据文本、答案与解析；证据缺失或答案有歧义时标记待审核。
- 网页刷题、提交、即时客观判题、解析查看、完整作答历史及错题列表。
- 复习状态与每日计划：到期题优先、弱项优先、考试日期和每日时长预算；计划可手工调整。
- 一个共享 Python 业务层，供 FastAPI API 和 Codex CLI 调用；项目根目录 `AGENTS.md` 规定 Codex 操作约束。
- CLI 操作与网页数据一致；最少提供导入、校验、审批/发布、查询计划及统计等接口。
- 本地数据备份与恢复说明，完整端到端验收测试。

### 2.2 MVP 不做（P1/P2 候选）

- 账号系统、多用户协作、云端同步、移动原生客户端。
- 自建 Agent Runtime、网站内部 AI 聊天框、无人值守的定时 Codex 代理。
- 必须依赖向量数据库、RAG 聊天、知识图谱渲染。
- 多选、填空、简答、代码题及主观自动评分（待 P0 稳定后再考虑）。
- OCR 扫描版 PDF、PPT/Word 导入、历年真题自动去重、跨课程知识融合。

## 3. 使用者与使用场景

- **学生（唯一网页使用者）**：建课、上传章节资料、刷题、看错题、设置考试日期、调整每日计划、人工审核题目。
- **Codex（外部操作代理）**：在用户授权指令下读取工作区、解析已导入课程资料、生成知识点与题目；必须通过 CLI/服务层完成写入；不得直接改写数据库或跳过状态机。
- **系统调度器（确定性程序）**：自动记录作答、维护题目复习状态，在打开当日页面或执行计划命令时计算/刷新日计划，不依赖 Codex 持续在线。

## 4. 关键用户旅程

**UC-01：新建科目及导入 PDF**

1. 学生创建“软件需求工程”，设置考试日期、每日复习预算，添加第三章。
2. 上传可提取文本的 `第三章.pdf`；系统保留原件、计算哈希并绑定科目/章节。
3. 若重复上传同一文件，系统提示已存在，而不是静默重复入库。

**UC-02：Codex 生成练习题**

1. 学生在 Codex 中打开本地项目，指令：“根据软件需求工程第三章 PDF 生成 20 道单选、10 道判断题”。
2. Codex 按 `AGENTS.md` 读取目标课程的资料；生成带来源定位的知识点及结构化题目。
3. Codex 调用 CLI 校验与导入；不确定题目进入 `needs_review`；只有满足明确发布策略的题目才可发布。
4. 网页能看到题目总数、已发布数和待审核数；人工审核时保留操作记录。

**UC-03：练题 → 错题 → 次日复习**

1. 学生选择课程和题量开始练习；默认只抽取 `published` 的题。
2. 提交答案后显示判题结果与依据；系统新增不可覆盖的 Attempt，更新 ReviewCard。
3. 答错的题出现在错题视图；重复答对不清除历史错误记录。
4. 次日打开“今日复习”，自动显示到期复习任务、弱点练习及预计用时。
5. 做完后计划和掌握状态更新。没有启动 Codex 时，上述功能依然可用。

## 5. 功能需求（带验收条件）

| ID | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-01 | P0 | 科目 CRUD 与考试日期、每日复习预算 | 建立两科目后，分别显示不同考试日期和进度，编辑互不干扰 |
| FR-02 | P0 | 科目下章节 CRUD | 同名章节在不同科目可共存，章节跨科引用被拒绝 |
| FR-03 | P0 | PDF 上传、存储、哈希与归属 | 重复文件能被检测；文本型 PDF 可定位页码；扫描型提示无法自动提取 |
| FR-04 | P0 | 题库结构化导入 | 输入遵循约定 schema；无效数据被拒绝并有错误报告；不产生半成功脏数据 |
| FR-05 | P0 | 题目质量校验与审核状态 | 缺失来源/无效答案/重复等进入拒绝或待审；未发布题不能进入普通刷题 |
| FR-06 | P0 | 单选和判断题练习 | 提交后可靠判题，写入 Attempt 并可查看解析及来源 |
| FR-07 | P0 | 错题与作答历史 | 同一道题多次练习记录完整；错题按知识点、科目可筛选 |
| FR-08 | P0 | 每日复习调度 | 页面打开可生成当天计划；支持考试日期、预算、到期题、薄弱项；无 Codex 可运行 |
| FR-09 | P0 | Codex CLI 与网页共享业务服务 | CLI 导入发布后刷新网页可见；网页作答后 CLI 报告可见；不允许 CLI 绕过校验 |
| FR-10 | P0 | 导出备份与数据恢复验证 | 备份后在测试目录恢复，题库数量、科目与历史作答一致 |
| FR-11 | P1 | 多选、填空、主观题 | 不进入 P0 验收范围 |
| FR-12 | P1 | 错题变式题生成与反例训练 | P0 稳定后设计去重与知识点覆盖 |

## 6. 业务规则与状态模型

### 6.1 数据作用域

- 每条 Chapter/SourceDocument/Question 均明确绑定 Subject；跨 Subject 引用必须被校验阻止。
- 一题可关联多个 KnowledgePoint；每个关联的证据应定位到具体原 PDF（至少文件 ID + 页码，尽量保存片段）。
- 课程原始 PDF 不被覆盖；文件替换视为新的版本或新导入。

### 6.2 题目生命周期（与现有 AGENTS.md 一致）

`draft → validating → (needs_review | approved) → published`；另有 `rejected`、`archived`。

- `needs_review`：人工确认/修改；`approved`：通过审核但未必发布；`published`：可以参与正式练习。
- 发布是通过业务层执行的独立动作；可审计，支持撤回/归档。
- 题目一旦被作答，修改答案应产生题目版本，不得回填改写旧 Attempt 所见答案。
- 任何题目缺少可验证来源或自动检查不通过，不得静默发布。

### 6.3 学习状态（每用户每题，不是题目本身状态）

`new / learning / review / relearning / suspended`。

- `Attempt` 是追加式答题事件；错题本是由历史作答或当前待巩固状态计算的视图，而非独立 `Question.is_wrong`。
- 复习调度应由确定性逻辑维护；后续可引入 FSRS。实际参数与新题混排比例在架构设计阶段通过 ADR 决策。
- 计划应记录生成时间、来源、手工修改和结果，避免前后不同页面给出矛盾任务。

## 7. 非功能需求与约束

| ID | 需求 | 可测试指标/约束 |
|---|---|---|
| NFR-01 | 本地优先 | 浏览器 + FastAPI + SQLite 在本机可运行，普通练习无需联网 |
| NFR-02 | 数据一致性 | API 和 CLI 使用相同 service 层；事务失败不可留下部分写入 |
| NFR-03 | 安全边界 | 外部 Codex 不直接写 SQLite；PDF 文本视为不可信内容，不可作为覆盖 AGENTS.md 的指令 |
| NFR-04 | 可恢复性 | 提供手工备份/恢复命令或等效能力；在干净目录完成恢复测试 |
| NFR-05 | 可用性 | 常规页面的本机交互响应目标 < 1 秒（不含 AI/大 PDF 处理）；长任务异步显示进度或阶段状态 |
| NFR-06 | 可维护性 | 类型化 API/CLI、数据库迁移、关键业务单元测试与端到端测试；避免逻辑散落在页面中 |
| NFR-07 | 可追溯性 | 题目从原文到生成、校验、发布有记录；可显示文件名、页码、证据 |
| NFR-08 | 隐私 | 默认绑定 localhost；数据库、原文件、备份都存本地；不将资料自动传外部云服务 |

## 9. 页面范围（MVP）

1. 首页/今日复习：展示当日计划、到期数、最近进度。
2. 科目列表/详情：章节、考试日期、PDF 资料、课程概况。
3. 题库与审核：各审核状态数量、待审题详情、发布/退回。
4. 练习页：单选、判断、答题反馈、原文证据。
5. 错题本/历史：按科目、章节、知识点筛选。
6. 设置：本地数据位置、备份说明、开发阶段诊断信息。

## 10. P0 端到端验收剧本

**E2E-01 课程闭环**：建科目 A、B → A 中创建第三章并上传文本型 PDF → Codex 为 A 第三章生成并导入题目 → 系统校验/送审/发布 → 前端只显示已发布题 → 作答产生历史及错题 → 系统为下一日生成复习任务 → 完成复习后计划更新 → 备份与恢复全部数据。

**E2E-02 隔离性**：A 中的文档、题目、错题不得被 B 的筛选或 Codex 对 B 的生成命令读入/修改。

**E2E-03 风险与回滚**：无来源或答案歧义题不得发布；重复导入同批次不得复制同一批题；发布后的题目修改需保留版本与已发生的 Attempt。

**E2E-04 Agent 离线**：关闭 Codex，仅运行网页和 FastAPI，仍可刷题、判题、查看错题、生成每日计划。

## 11. 待裁决事项（需求评审时确认；推荐默认值）

| 编号 | 事项 | 推荐默认 |
|---|---|---|

| D-02 | AI 调用执行者 | Codex 是外部 Agent，网站本身不调用 LLM |
| D-03 | 题型范围 | P0 单选与判断；多选、主观题后续 |
| D-04 | 来源格式 | 先支持可提取文本的 PDF；OCR 后续 |
| D-05 | 自动发布策略 | 强校验无误者可批准并发布；有疑问强制人工审核，所有发布操作可审计 |
| D-06 | 每日调度策略 | 先实现确定性调度和时间预算；是否上 FSRS 留给技术设计 ADR |
| D-07 | 工作区与文件 | 所有课程存本地工作区；SQLite 作业务真实来源，Markdown 是知识材料 |
