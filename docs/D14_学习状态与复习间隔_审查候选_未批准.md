## 1. D-14 必须确定的可观察行为

1. **粒度**：建议每个有效逻辑题目一张学习卡（ReviewCard），不为同一道题维护两个互相冲突的计划；知识点仅聚合薄弱证据，属于 D-23 后续统计。
2. **状态**：`new` 未正式判题、`learning` 学习中、`review` 间隔复习、`relearning` 已确认做错后重新巩固、`suspended` 暂停。暂停需保存被暂停前状态和到期信息。
3. **事件**：四题型已确认的正确/错误作答均记录追加式 Attempt（重复提交幂等由 D-22 定义）；同一个作答只推进一次卡片。待复核填空不进入错误历史、不改变依赖对错的调度，最终判定时由 D-22 保障一次生效。
4. **入口**：普通练习与计划练习采用一致的学习状态转移规则，记录事件来自何处；失效/归档版本不允许开始新练习（D-10）。
5. **暂停**：默认不进入自动计划；建议允许主动练习并记录，但不自动解除暂停，也不改变冻结的自动调度状态。恢复后按可解释的到期规则重新纳入。
6. **时间**：必须明确第一次答对/答错、连续答对、复习错误时的下一次到期时间；保持同输入、同规则与同逻辑时刻下结果唯一。时间基准与考试日加权需衔接 D-16，而不能在这里默许 D-16 的候选时区生效。

## 2. 三种可选调度方式（仅供产品负责人裁决）

### 方案 A：固定间隔 + 自动二值判定（推荐 MVP）

- 不额外增加学生的“简单/困难”评分步骤：按正确/错误更新，所有已确认作答统一适用。
- 建议候选间隔（相对于正式判分生效时刻）：
  - 初次答错或任意非暂停状态下再次答错：转 `relearning`，**10 分钟后到期**；继续答错则每次再延长 10 分钟。
  - 初次答对：转 `learning`，**24 小时后到期**。
  - `relearning` 中答对：转 `learning`，**24 小时后到期**，连对阶段重新开始。
  - `learning` 中再次答对：转 `review`，**72 小时后到期**。
  - `review` 后持续答对：后续间隔依次为 **7 天、14 天、14 天……**，直到以后批准调整为止。
- 已到期但未做：保持当前状态并标记 overdue，不凭空生成 Attempt，也不自动宣布掌握。
- 当天到期的题是否列入待巩固：建议仅包含有效已发布题中 `learning/relearning/review` 且到期（`due_at <= now`）的对象；未到期可在“未来安排”查看。新题通过单独“新题”入口/每日计划出现，不混入“历史错题”。此定义与 D-13 的“待巩固”视图衔接，需要产品确认。
- 暂停期间允许用户手动练题：保留作答历史，但不改自动调度卡；恢复时保留原 due_at，若已过期立即到期，不自动顺延。
- 优点：MVP 容易实现、调试和逐条验收；缺点：不会根据不同题目记忆难度优化间隔，属于后续升级的起点。

### 方案 B：FSRS 风格调度（MVP 引入）

- 一题一卡，使用已确认正误映射调度；需要决定是否追加“困难/一般/简单”主动自评。如果只用二值，调度输入简洁，但个性化信息更少。
- 具体 FSRS 版本、参数与技术实现放在设计 ADR；**需求基线前仍必须批准**同事件固定样例的可复现预期、正确/错误映射、首次与错后行为、待复核及暂停规则，并用冻结参数产生验收结果。
- 优点：后期更容易针对记忆曲线调整；缺点：MVP 行为更难人工核验，参数迁移和卡片历史语义复杂。

### 方案 C：自定义

- 用户自定复习节奏、评分输入、首次正确与首次错误后的状态/间隔；需形成固定事件序列与验收预期后才能批准。

## 4. 验收门槛（待补入 SRS v0.2 和追踪矩阵）

1. 一题只有一张当前有效的调度卡；无作答是 new，题目发布与未发布状态不会凭空生成错误历史。
2. 首次正确、首次错误、连续正确、再次错误、暂停、恢复及到期但未做时，状态与下次到期可复现；测试不用等待真实时间，采用逻辑测试时钟。
3. 同一逻辑提交重复发送，Attempt/卡片只改变一次；主动发起第二次练习才追加事件（事务要求最终由 D-22 决定）。
4. 未确认的填空答案不产生已确认错题历史、不推进对错驱动卡片；人工复核后的生效过程由 D-22 规定。
5. 归档/失效版本历史可查但不进入新计划；新版本迁移方式按 D-10 确认。
6. 前端与 Codex CLI 在同输入/同测试时刻下显示一致的状态与到期时间。
