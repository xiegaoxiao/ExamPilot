## 1. 阅读约定与验收环境

- **既定**：原 SRS/AGENTS 已明确的约束；**细化**：为使需求可测提出的建议，须经关联 D 决策确认。混合用例不能在细化项未定时标记全部通过。
- N/X/I 分别为正常、异常、跨科目隔离；BC 为交叉边界检查；NF 为非功能检查。编号仅是需求/验收标识，不代表自动化测试已实现。
- UC-01～03、E2E-01～04 沿用 SRS；UC-R04～09 是为遗漏动作补充的用例草案，不增加未授权的产品阶段或功能范围。
- 验收使用独立的合成/获准测试资料，不删除、覆盖、批量重置用户现有 PDF、已发布题或 Attempt；备份恢复仅在测试目录完成。
- 固定环境：登记产品版本、OS/浏览器/硬件、时区、逻辑测试时间、输入资料哈希及已批准规则版本。候选性能负载见 D-21，未定数值不能以实现默认值填补。
- 公共数据：科目 A“软件需求工程”、B“操作系统”，各有同名“第三章”，A 另有第四章；文本 PDF 至少含两物理页，并有印刷页与物理页不同的样例。A/B 知识点可同名但身份独立。
- 题目样例覆盖单选、判断及全部审核状态；错误样例包括坏格式、跨科关联、缺证据、歧义、完全重复、疑似重复和不存在的选项答案。历史样例覆盖对→错、错→对和多版本。
- 每项留存前置快照、操作输入、网页结果或 CLI 摘要、后置业务查询、审计/事件依据。计数、状态与内容同时检查，不能只凭“界面看起来正常”通过。

## 4. 每条 P0 的正常、异常、隔离验收

每组共用第 1 节夹具；“无变化”均指目标业务数据和其他科目数据无非授权变化，失败审计可按已批准规则记录。凡按 ID 访问的检查，不得仅靠下拉框隐藏错误选项完成。

| 检查 | 前置与操作 | 通过判据及性质 |
|---|---|---|
| AC-01-N | 新建 A/B，设不同考试日期和预算；查询、改名和编辑设置；删除一个无引用测试科目 | 两个独立 ID；重新打开仍显示各自设置，编辑 A 不改变 B；空对象删除结果符合 D-08。隔离/持久化为既定，删除细则为细化 |
| AC-01-X | 提交空白名称、不合法日期/预算；尝试删除已有 PDF、已发布题和 Attempt 的 A | 非法输入有具体字段原因；受保护数据不被无授权删除，历史及原件仍可访问。输入边界按 D-21；保护既定，拒绝/归档动作按 D-08 |
| AC-01-I | 在 A 上下文用 B 的科目 ID 发起课程设置修改/归属不一致操作 | 拒绝范围冲突，B 的设置/题目/历史均不变；正常切换到 B 后才可执行 B 的操作。既定隔离，D-09 细化入口口径 |
| AC-02-N | A/B 各建同名第三章；在 A 内查询、改名；创建并删除空测试章 | 两章各归唯一科目；同名跨科允许；章节及排序/名称刷新一致，空章删除按 D-08。既定与细化 |

## 5. 交叉边界与业务规则检查

以下检查细化多个 FR 的共同风险，所有依赖决策的精确断言均须先确认。测试时间可由未来测试环境控制，不等待真实过夜，也不直接修改业务数据库造假。

| 检查 | 场景、输入与预期 | 关联 / 决策 |
|---|---|---|
| BC-01 来源定位与 PDF 失败 | 验证 PDF 第 1 页/末页，0/负数/越界页不可作有效证据；印刷页不同仍定位正确物理页；片段在所指页可核验。混合 PDF 的扫描页不伪造文本，损坏/超限给原因；同名新内容不覆盖原件 | FR-03/05；D-12/18/21 |
| BC-02 同名、同哈希与章节边界 | A/B 同名第三章、知识点保持独立；A 第三章指令不得自动读 A 第四章；若显式同科多章请求按批准范围取材。相同字节跨科/章按 D-18 独立处理，不共享知识/题/审核记录 | FR-01～05/09；D-09/17/18 |
| BC-03 审核许可与发布摘要 | 覆盖 draft/validating/needs_review/approved/published/rejected/archived 的合法及非法动作；仅 approved 可进入发布；未知校验结果进入待审，缺来源/多解不得硬放行。批量摘要与实际对象/版本一致，成功、失败及自动规则依据可审计；失败项不冒充发布 | FR-05/09；D-05/12/24 |
| BC-04 发布版本与在途提交 | 无 Attempt 的已发布题改答案也创建新待审版；旧版已有 Attempt 的答案/结果不变；新版发布后抽题资格唯一明确；原版失效时正在作答/计划内题按批准策略提示且不篡改历史；卡片变化可解释 | FR-05～08；D-10/22 |
| BC-05 批次原子性与幂等 | 全有效、坏结构混合、质量问题混合、完全/疑似重复混合分别操作；同键同内容重试新增数为 0，同键异内容拒绝；相同内容新键不绕过去重；提交失败不留半批业务成果，报告数量可核对 | FR-03/04/09；D-11/12 |

## 8. P0 端到端验收剧本

### E2E-01 课程闭环

1. 在获准测试工作区建 A/B 及各自第三章，设置已确认的日期与预算；A 上传文本 PDF，B 保持独立资料。
2. 显式仅对 A 第三章请求 Codex 生成带知识点与来源的单选/判断题；记录实际请求数与产出数，不承诺资料不足也必须强行凑题。
3. 导入、校验、送审，按批准策略发布可验证题；网页题库可查看所有状态，**普通练习仅展示有效已发布题**。题库审核页不能误验为只显示发布题。
4. 网页至少分别完成两题型的正确/错误样例，核对追加历史、解析、来源及错题；记录卡片与计划变化。
5. 使用已批准调度样例控制测试时钟，使至少一题确实在下一日到期；无 Codex 打开当日计划、完成任务，核对预算和计划更新，不假定所有错题都必然次日到期。
6. 备份恢复到干净测试目录，核对全量状态与来源，并继续一次练习。

通过：AC-01～10 的正常项、NF-01/04/07 均满足；产出/发布/待审/Attempt 数能核对，全部业务引用保持归属；原工作区无破坏性变更。

### E2E-02 隔离性

用 B 的请求上下文依次访问/更新 A 的章节、文件、证据、知识点、题目/版本、历史、卡片、计划项、任务及统计；同时验证同名与同哈希。再反向测试 A→B。

通过：AC-01～10 的隔离项全部满足；越范围详情、批量及文件路径同样被拒绝，无泄漏或污染。明确的全局首页汇总/全工作区备份按批准范围单独检查；不要求本轮实现 OS 级 Agent 沙盒。

### E2E-03 风险、重试与版本保护

分别导入无来源、多解、非法结构、跨科、完全/疑似重复样例，执行非法发布、失败重试与重复提交；修订一个已发布但未作答题和一个有旧 Attempt 的题，校验旧版本与在途处理。

通过：AC-04/05/06 异常项、BC-03～06 满足；缺证据或歧义题不发布，重复操作不复制成果，失败不留部分业务状态；所有原作答关联及旧判分保留。此处“回滚”指失败操作原子不生效，不是重置用户历史。

### E2E-04 Codex 离线

在本机依赖已准备、资料与题目已导入后，关闭 Codex 并断网，仅启动网页/FastAPI；执行抽题、判题、历史错题、当日计划生成与调整、到期任务完成。

通过：上述能力全部可用，重新打开仍持久一致；网站未自动请求外部 AI。新 AI 出题不计入离线承诺。

## 9. MVP 验收门槛及记录

**需求基线门槛**：先关闭评审阻塞问题、确认 D 决策，将待定输入边界/事件样例/测量口径写入需求修订版并经用户批准。当前不满足该门槛。

**未来产品验收门槛**：在基线获批、实现完成后，全部 FR-01～FR-10 的 N/X/I 检查、BC-01～14、NF-01～08 和 E2E-01～04 按批准条款通过；不能用平均通过率豁免任何 P0，也不能只跑 happy path。跨科污染、无证据发布、历史丢失/改写、重复作答记账或无法恢复均不得带入通过结论。FR-11/12 保留为后续范围，不因本轮未验收而删除。
