# ExamPilot SRS v0.1 正式需求评审报告

- 评审日期：2026-10-21
- 阶段：01 软件需求分析
- 被评审版本：`docs/SRS_v0.1.md`，2026-10-21，候选基线
- 约束依据：根目录 `AGENTS.md`、`Codex_阶段01_需求评审任务.md`
- 评审方式：文档静态评审；未运行产品、未开展实现验证。
- 评审结论：**需修订后复审，当前不建议冻结需求基线。** 本轮评审交付完成不等于需求已获批准。
- 交付关联：[需求追踪与验收草案](../requirements_traceability.md)、[待决策清单](../open_decisions.md)。

## 1. 结论与范围保全

SRS 已明确目标用户、P0 题型、资料范围、外部 Codex 边界、共享业务入口、追加式作答历史和离线复习闭环。题库生命周期与学习状态分离的方向正确，具备继续细化需求的基础。

尚未达到冻结条件的原因是：若直接据此实现，不同开发者会对删除保护、隔离范围、发布授权、版本有效性、批次失败、复习状态和计划更新得出不同结果，现有验收条件无法唯一判定这些结果是否正确。

本报告记录 **24 项问题：8 项阻塞、12 项重要、4 项一般**。严重度表示需求澄清的优先程度，不表示现有软件已存在缺陷。所有问题均为开放状态，提出建议不视为解决。

本轮保留全部已明确 P0：科目/章节管理、考试日期和预算、文本 PDF、知识与来源、单选和判断题、导入校验与审核发布归档、练习判题、历史错题、确定性复习及手工计划、CLI/API 一致、备份恢复。FR-11、FR-12 继续保留为 P1，不纳入 P0 交付；不新增 OCR、多用户或内置 Agent Runtime。

**本轮仅新增评审文档，不修改原始 SRS 或 AGENTS，不编写前后端业务代码，不创建数据库、物理表、API 设计或技术 ADR，不进入下一开发阶段。**

## 4. AGENTS 与 SRS 差异判定

| 事项 | 判定 | 处理意见 |
|---|---|---|
| 已发布题改答案 vs 被作答后改答案 | 实质约束差异，SRS 较弱（RV-04） | 按 AGENTS 已发布即版本化的保护要求补正；不以“尚无人作答”允许静默改写 |
| 证据片段“保存” vs “尽量” | SRS 内部及与 AGENTS 的强度差异（RV-11） | 基线前统一；缺来源题可进入待审，但批准本身不能凭空补足证据 |
| CRUD 与原 PDF/历史/已发布题保护 | 未定义协调规则（RV-01） | 不是直接取消删除，而是定义受保护对象的可接受删除边界 |
| AGENTS 单选开发步骤 vs SRS 单选+判断 | SRS 对 P0 的明确扩展，无禁止性冲突 | 两类均纳入验收，不删判断题 |
| AGENTS 每题/知识点复习卡 vs SRS 每题 | 粒度未统一（RV-06） | 推荐每题调度、知识点聚合弱项，待用户确认 |
| 通用知识可验证例外 vs PDF 必备 | 例外未闭合（RV-11） | P0 优先课程 PDF；是否容许非 PDF 来源及其验收仍需决策 |
| AGENTS CLI 示例 vs SRS 能力范围 | 示例明确尚未实现，不能当现有能力 | 评审不调用、也不补写 manage.py；仅形成未来能力验收 |
| AGENTS 变式题自然语言示例 vs FR-12 P1 | 愿景与当前版本范围差异 | 明确保留 P1，不以示例提前扩展 P0 |
| 外部 Codex 与本地优先 | 可以兼容，但隐私表述不完整（RV-08） | 离线保证覆盖练习/复习；AI 处理边界另行明示 |

## 5. 三个关键业务判断

### 5.1 科目与章节隔离

以显式 `subject_id` 为处理上下文，名称用于定位但不能替代唯一身份；有多个同名对象时先消歧。指定 chapter 后，文档、知识点、题目及证据必须满足已确认章节范围。科目级查询允许包含该科目多个章节，不能混入其他科目。首页汇总不是跨科混用生成材料的许可。

隔离既要约束列表，也要约束按 ID 详情、证据打开、导入、发布、作答、计划、任务重试、统计以及允许的业务文件访问。相同 PDF 字节或相同知识点名称不构成跨科复用授权。备份可能明确覆盖全工作区，须与课程操作区分。

外部 Codex 可以读取项目文件，所以此处有两种保证：业务入口技术校验，以及 Agent 按授权选择材料的操作约束。仅凭本地文件夹或 CLI 参数，不能证明外部进程在操作系统层无法读取其他科目。

### 5.2 题库生命周期

现有状态集合合理，但简图不足以完整表达审核与发布的业务许可。需求层应明确：草稿不可练；校验不确定进入待审；审核通过仅使其可发布；正式发布是独立受审计动作；拒绝/归档题不可进入新的普通练习与计划。撤回是归档还是返回审核，修订题应回到哪种状态，均见 D-05/D-10，当前不认定已批准某种完整状态机。

来源缺失、答案不可判断不能因人工点击批准而被当作已验证。新版本发布前，旧有效版是否继续使用必须统一；历史 Attempt 永远按当次版本解释，不回写旧对错。普通练习入口和复习入口适用同一题目资格限制。

### 5.3 错题、学习状态与每日计划

答错是学习者事件，不是全局题目状态；历史错题集合与当前待巩固集合应分开表达。答对不能删除过去答错，也不能直接说明某知识点已全面掌握。归档题可保留历史，但新计划只安排有效已发布题。

复习卡应由真实作答和暂停/恢复事件驱动。计划的“完成”不能伪造 Attempt 或掌握度。预算内做不完全部到期题时必须展示延后项及原因；用户调整计划后刷新页面不能无声覆盖。次日验收应使用已确认规则下确实次日到期的样例，不能假定所有题第二天都到期。

## 6. 场景覆盖结论

[追踪矩阵](../requirements_traceability.md) 为 FR-01～FR-10 各设置正常、异常、隔离三类用例，共 30 项；另有 14 项交叉边界用例、8 项 NFR 检查和原有 4 条 E2E 的细化剧本。

- 正常：创建两科、文本 PDF 导入、知识与两类题生成、审核发布、练习、错题、离线生成计划、完整恢复。
- 异常：结构不合法、错误归属、恶意 PDF、来源/答案问题、磁盘或业务失败、网络重试、损坏备份、外部 AI 中断。
- 边界：同名跨科、同哈希跨范围、混合 PDF、缺省/过期日期、零预算、到期超预算、零可练题、版本失效、并发更新、午夜切日、手工计划刷新、恢复路径迁移。

这些是验收草案，不是已执行的测试结果；依赖待决策项的断言在决策后才能成为正式通过条件。

## 7. 需求基线准入条件

1. 对 RV-01～RV-08 作出明确业务决策，原文 D-01～D-07 全部记录确认或修订结论。
