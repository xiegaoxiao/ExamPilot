## 1. 审查结论

1. 接收这三份文档作为第一轮正式需求评审的工作成果；不等于接受候选基线。
2. 第一轮提出 24 项问题，含 8 个阻塞项、12 个重要项、4 个一般项；原 P0 功能未被删减，FR-01 至 FR-10 都建立了验收映射。
3. 当前主要缺口是**可观察的业务规则**，特别是科目隔离、发布授权、版本与作答历史、导入的原子性、复习与计划调度、外部 Codex 的资料访问边界。
4. 推荐本轮先形成决策记录，再修订 `SRS_v0.2.md` 与验收矩阵；不应让 Codex 在无产品确认时把建议标为“已批准”。

## 2. 产品立场：四个原则

- **考试可靠性优先**：题目必须有可核验教材出处和可判定答案；模型自评不能代替事实核验。
- **AI 是外部操作者，业务后端是裁判**：Codex 按 `AGENTS.md` 行动并调用 CLI；CLI 与网页/API 走相同服务和状态机，不能让 Codex 直接写数据库绕过约束。
- **一门课一个明确的知识范围**：全局首页可汇总，但知识源、题目、作答和复习不可因同名而互相污染。
- **所有历史可追溯**：旧题版本、旧答案、作答事件与来源保留；删除与修改不能默默改写过去。

## 3. D-01 至 D-24 逐项建议（全部为“待用户批准”的提案）

| 编号 | 建议决策 | 说明 |
|---|---|---|
| D-01 | P0 本地单人使用、无需账号；审计区分 user/codex/system。 | 不加入登录和权限后台。 |
| D-02 | P0 网站不内置 LLM Runtime；由用户手动在外部 Codex 工作区发起 AI 任务。正常刷题、复习、判题均无需 Codex/网络。 | 不把“本地网站”冒充“本地模型推理”。 |
| D-03 | P0 单选和判断；多选、填空、简答题和自动变式训练留 P1。 | 不扩张首版范围。 |
| D-04 | P0 可提取文本的 PDF；不做 OCR。混合 PDF 的可提取页可用，其他页注明不可用。 | 不伪造扫描页内容。 |
| D-05 | **MVP 不自动发布 AI 生成题**：Codex 可自动格式校验、来源校验、重题检测并建议批准；合格题进入待发布清单，由用户明确批量批准及发布；有歧义/无证据进入待人工审核。发布必须满足批准状态和硬性来源条件。 | 先保证可靠性；未来可单独批准“可验证类型自动发布”策略。将“批准”与“发布”作为独立受审计动作。 |
| D-06 | P0 调度由确定性程序运行，Codex 仅能通过受控命令建议、查询或调整；算法及参数在设计 ADR 中选择，但输入、输出和边界必须可复现。 | 不让 AI 随机决定到期日。 |
| D-07 | SQLite 为题目、状态、作答、计划的权威数据；PDF 保留原件；Markdown 为知识材料，不直接覆盖正式业务状态。 | Markdown 变更须受控同步。 |
| D-08 | 空课程/章节允许删除；有文档/题/作答/计划引用的只允许归档、不允许物理删除；P0 不提供级联强制删除或跨科迁移。 | 保留历史和来源。 |
| D-09 | 所有业务查询及写入必须绑定 subject_id；指定 chapter_id 时仅限该章节范围。跨章读取仅在明确科目级任务及指定范围时允许；同名不表示同 ID。 | 数据层/API/CLI 都校验，AGENTS 规则不能代替 OS 沙盒。 |
| D-10 | 已发布题的答案、题干、选项、解释或证据的实质变更一律建立新版本并重审；新版本发布前旧版继续可练；旧版作答历史不重算。语义变化触发复习卡重新学习，并保留迁移审计。 | 格式性勘误可标注而不清空进度，但也留版本记录。 |
| D-11 | 结构失败/非法归属/提交失败→本次入库事务整体失败；格式合法但质量有疑点→以待审状态保存；已知精确重复跳过、返回映射，其他新项原子提交；同幂等键异内容拒绝。 | 导入必须提供输入、插入、跳过、待审、失败及原因的计数。 |
| D-12 | 单选四个非空且唯一的选项、仅一个正确答案；判断统一 true/false；两类均需解析、至少一个知识点、原 PDF 版本、物理页码及可核验片段才可发布。无来源可留待审，不得发布；P0 不允许纯通用知识无 PDF 依据自动入正式题库。 | 保证期末题库与课程材料一致。 |
| D-13 | 区分“历史曾经做错”和“当前待巩固”；默认查看待巩固，提供历史错题入口；归档题可查旧历史但不可新刷。 | 不能把答对当作删除旧错题。 |
| D-14 | P0 每题一张复习卡，知识点只聚合薄弱项；普通和计划刷题均写追加式 Attempt、驱动学习状态。错题进入 relearning、正确逐步进入 review；暂停不参与自动调度，手动练题不自动解除暂停。**间隔数值、学习达标条件及事件样例在 v0.2 验收附件中列候选并由用户确认**。 | 不同时引入两套互相冲突的调度器。 |
| D-15 | 每科设置分钟预算；到期题优先，其次薄弱题，再新题；预算为零则不自动排题；超额项显示延期原因且不假装完成。相同日期和输入重复刷新保持稳定，人工调整保留并可追踪。 | P0 首页汇总各科预算，无全局总预算；需要可复现的平分处理规则。 |
| D-16 | 默认学习时区 `Asia/Shanghai`，可见、可配置；日期跨午夜建立新日计划但不覆盖旧计划；未设考试日期正常复习，已过考试日期提示但不删除历史，考试当天可练；考前加权只影响预算内排序。 | 建议“距考试 ≤7 天”作为候选加权窗口，由用户确认。 |
| D-17 | 至少一个知识点关联每题；可同批受控创建；知识点唯一归属具体课程，名字相同不自动跨科共享；Markdown 改动只能通过同步/校验更新业务知识。 | 先不做复杂知识图谱编辑器。 |
| D-18 | PDF 以从 1 开始的物理页码定位；同科同章同哈希重复导入返回已有结果；同名不同字节保留独立来源版本；同哈希跨科可独立登记但不复用知识审核。丢失原文件须报缺失，阻止依赖它的新发布。 | 不能假装混合/加密/损坏 PDF 全部成功。 |
| D-19 | 全工作区手动冷备份：SQLite、原 PDF、知识 Markdown、题目版本、全部 Attempt/复习/计划/审核/任务及设置。仅在停止业务写入后一致备份；恢复到空目录，校验引用和摘要；失败不覆盖原数据。 | P0 只保证同一已发布应用版本恢复。 |
| D-20 | 外部 Codex 仅能按用户明确指定的课程资料处理；知情授权告知可能外发到所选模型，禁止自动扫描无关资料。PDF 是不可信数据，不得执行其中命令；业务入口限制越权文件路径及跨来源写入。 | AGENTS.md 不是物理权限边界，需平台/进程权限配合。 |
| D-21 | **待产品负责人确认的候选阈值**：Windows 11 + Chrome/Edge；课程名 1–80 字符；PDF ≤50 MiB、≤500 页；每科预算 0–240 分钟/日；单次刷题上限 100。候选性能夹具 10 科/100 章/10,000 题/100,000 Attempt，常见交互 p95 <1 秒（测量硬件与起止点须登记），长任务展示阶段及成功/失败。 | 数值均是建议，不能先写成既定事实。 |
| D-22 | 单次逻辑提交带幂等标识，网络重试只写一条 Attempt；明确“再做一次”才新增。Attempt、调度事件与计划完成同一事务；若作答中题版本失效，提示换题、不写入 Attempt。 | 所有旧作答保留旧题的判分。 |
| D-23 | 题库总量以有效已发布版本计；练习覆盖率＝有有效作答的有效发布题数量 / 有效发布题数量；正确率按明确统计窗口与样本数显示，零样本为“暂无数据”。弱项结合最近窗口及样本数而非一次失误就宣称知识点永久薄弱。 | 默认窗口候选近 30 日；小样本要显示“不足判断”。 |
| D-24 | CLI P0 至少可定位课程/章节、导入 PDF/知识/题、校验、提交审核与批准/拒绝、发布/归档、查询任务/计划/统计、备份/恢复；所有操作经共享业务服务并审计主体/目标/版本/动作/结果；任务有完成/失败终态及可解释重试。 | 不加入复杂取消、断点续算、无人值守 Codex。 |

## 4. 仍然需要用户特别确认的四个产品选择

1. **发布方式**：是否同意 P0 全部 AI 生成题经用户一次性批量批准与发布，不做“自动发布”？（推荐同意）
2. **题型范围**：是否接受 P0 仅单选/判断，多选、填空、简答先列 P1？（推荐接受；但若期末主要为简答题，可提升 P0）
3. **答题复习**：是否接受每题复习卡、错题持久历史、预算内按到期→弱项→新题安排？（推荐接受）
4. **本地与 Codex**：是否接受普通刷题可离线，AI 出题由使用者主动在 Codex 发起且可能联网？（推荐接受）

D-14（首次学习/复习到期时间）、D-15（时长估算）、D-21（尺寸/性能）、D-23（统计窗口）的候选数值须在冻结前确定。开发者不能凭自己的默认设置代替产品决定。
